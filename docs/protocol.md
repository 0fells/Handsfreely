# Протокол Handsfreely, версия 1

Канал между программой на ПК и приложением на телефоне. Транспорт: Bluetooth RFCOMM. ПК слушает службу с UUID `e7530220-2b8a-460d-925c-0267c9b9b467`, телефон - службу `1c3afcb6-f84e-400c-9554-6c9dd39596a3`; подключиться может любая сторона (телефон - когда связи нет, ПК - при запуске программы). Рукопожатие от этого не зависит: его всегда начинает телефон. Если соединений с одной парой ПК-телефон оказалось два, обе стороны оставляют последнее установленное. Звук разговора по этому каналу не идёт: его переносит стандартный профиль HFP, которым управляет Windows. SMS тоже идут мимо канала: ПК читает и отправляет их сам по стандартному профилю Bluetooth MAP, поэтому приложению на телефоне не нужны разрешения на SMS (из-за них Google Play Защита блокирует установку не из магазина).

## Криптография

- Кривая P-256 (secp256r1), ECDH, открытый ключ в несжатом виде: `0x04 || X || Y`, 65 байт.
- HKDF-SHA256, AES-256-GCM с тегом 16 байт.
- У ПК и у телефона есть постоянные пары ключей (`static`). На каждое подключение обе стороны создают одноразовые пары (`eph`).

## QR-код сопряжения

ПК показывает строку:

```
handsfreely:1?a=<MAC>&k=<ключ>&t=<токен>&n=<имя>
```

| Поле | Значение |
|---|---|
| `a` | MAC-адрес Bluetooth ПК, 12 шестнадцатеричных цифр без разделителей |
| `k` | постоянный открытый ключ ПК, base64url без `=` |
| `t` | одноразовый токен, 16 случайных байт, base64url без `=`; живёт 5 минут, сгорает после успешного сопряжения |
| `n` | имя ПК, URL-кодирование |

## Кадры

Каждое сообщение в обе стороны: длина `u32` big-endian, затем тело. Длина больше 8 МиБ - разрыв соединения.

## Рукопожатие

```
M1 телефон -> ПК: "HF" 0x01 | mode (1) | phoneStatic (65) | phoneEph (65)
M2 ПК -> телефон: "HF" 0x01 | status (1) | pcEph (65, только при status = 0)
```

`mode`: `1` - сопряжение по QR, `2` - повторное подключение.
`status`: `0` - продолжаем, `1` - телефон неизвестен (нужно сопрячь заново), `2` - на ПК сейчас не открыто окно сопряжения, `3` - неподдерживаемая версия. При ненулевом статусе ПК закрывает соединение.

ПК отвечает `1`, если `mode = 2`, а `phoneStatic` нет в списке доверенных.

Ключи:

```
h    = SHA256("Handsfreely/1" || pcStatic || M1 || M2)
ikm  = DH(phoneEph, pcEph) || DH(phoneEph, pcStatic) || DH(phoneStatic, pcEph) [|| token, если mode = 1]
okm  = HKDF-SHA256(ikm, salt = h, info = "Handsfreely/1 keys", 64 байта)
kUp   = okm[0..32]   телефон -> ПК
kDown = okm[32..64]  ПК -> телефон
```

`DH` - сырой общий секрет ECDH (координата X, 32 байта). Расчёт доказывает обе стороны: `DH(phoneEph, pcStatic)` может посчитать только владелец ключа ПК, `DH(phoneStatic, pcEph)` - только владелец ключа телефона. Ключ ПК телефон знает из QR, поэтому подменить ПК нельзя. Токен в `ikm` подтверждает, что телефон видел QR.

Дальше все кадры зашифрованы: тело кадра = `AES-256-GCM(key, nonce, plaintext)` с тегом в конце, `nonce = 00 00 00 00 || u64 big-endian счётчик`. У каждого направления свой счётчик, он начинается с 0 и растёт на 1 с каждым кадром. Кадр, который не расшифровался, - разрыв соединения.

Первый зашифрованный кадр телефона - `hello`, ответ ПК - `welcome`. Если ПК не смог расшифровать `hello` (неверный токен или чужой ключ), он молча закрывает соединение. После `welcome` при `mode = 1` ПК добавляет `phoneStatic` в доверенные.

## Сообщения

Открытый текст кадра - JSON в UTF-8:

```json
{"t": "тип", "id": 7, "d": { ... }}
```

- Запрос: `t` и `id` (целое, уникально для отправителя), данные в `d`.
- Ответ: `{"t": "result", "id": 7, "d": {...}}` или `{"t": "error", "id": 7, "d": {"code": "...", "message": "..."}}`.
- Событие: `t` и `d` без `id`.

Коды ошибок: `unknown_type`, `bad_request`, `permission` (на телефоне нет разрешения), `unsupported`, `failed`.

### Рукопожатие приложения

| Тип | Кто | `d` |
|---|---|---|
| `hello` | телефон | `name`, `model`, `appVersion`, `sdk` |
| `welcome` | ПК | `name`, `appVersion` |

### Запросы ПК -> телефон

| Тип | `d` запроса | `d` ответа |
|---|---|---|
| `ping` | - | - |
| `device.info` | - | `name`, `model`, `battery`, `charging`, `signal` (0..4), `operator`, `callControl` (`full` или `basic`), `permissions` (массив выданных: `contacts`, `calllog`, `phone`) |
| `contacts.list` | - | `contacts`: `[{id, name, starred, hasPhoto, phones: [{number, type}]}]` |
| `contacts.photo` | `id` | `data` (JPEG, base64) или `null` |
| `calllog.list` | `limit`, `before` (мс, необязательно) | `calls`: `[{id, number, name, type, date, duration}]` |
| `call.dial` | `number` | - |
| `call.answer` | - | - |
| `call.reject` | - | - |
| `call.end` | - | - |
| `call.hold` | `on` | - |
| `call.mute` | `on` | - |
| `call.dtmf` | `digit` (`0-9`, `*`, `#`) | - |
| `call.audio` | `target` (`pc` или `phone`) | - |

`type` номера: `mobile`, `home`, `work`, `other`. `type` звонка в журнале: `in`, `out`, `missed`, `rejected`, `blocked`, `voicemail`. Время везде - миллисекунды Unix.

`call.hold`, `call.mute`, `call.dtmf`, `call.audio` работают при `callControl = full` (телефон выдал приложению роль спутника звонков). При `basic` телефон отвечает `unsupported`, и ПК пробует сделать то же через Windows.

### События телефон -> ПК

| Тип | `d` |
|---|---|
| `call.state` | `calls`: `[{id, state, number, name, direction, since}]` - полный список текущих звонков; пустой массив, когда звонков нет |
| `device.status` | `battery`, `charging`, `signal`, `operator` |
| `contacts.changed` | - |
| `calllog.changed` | - |

`state`: `ringing`, `dialing`, `active`, `holding`, `disconnected`. `direction`: `in`, `out`.

Неизвестный тип события получатель пропускает, на неизвестный запрос отвечает `unknown_type`.
